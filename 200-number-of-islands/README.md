# LeetCode 200 - Number of Islands

## 題目

給定一個由 `'1'`（陸地）與 `'0'`（海洋）組成的二維地圖，請計算共有幾座島嶼。

島嶼由上下左右相連的陸地所組成。

---

# 第一個想法

剛看到這題時，我並沒有立刻想到 DFS 或 BFS。

我的第一個想法反而是：

> **如果今天是在設計一套系統，我會怎麼拆解這個問題？**

仔細觀察後，我發現這個問題其實可以拆成兩件完全不同的工作。

1. 地毯式搜尋整張地圖。
2. 找到一座島後，把整座島處理掉。

這兩個工作互相合作，就可以完成整個問題。

---

# 系統架構

```
                +----------------------+
                |      主迴圈          |
                |----------------------|
                | 地毯式搜尋整張地圖   |
                |                      |
                | 發現 '1'             |
                | island_count++       |
                | clear_island()       |
                +----------+-----------+
                           |
                           |
                           v
                +----------------------+
                |   clear_island()     |
                |----------------------|
                | 將整座相連的島嶼      |
                | 全部清除             |
                +----------------------+
```

主迴圈完全不需要知道島嶼有多大、形狀長什麼樣。

它只有一個責任：

> **找到第一塊陸地。**

剩下的工作全部交給 `clear_island()`。

---

# 地毯式搜尋

把主迴圈想像成**地毯式搜尋**。

它就像一個掃描器，一格一格往前掃。

```
□□□□□□□□
□□□□□□□□
□□□□□□□□
□□□□□□□□
```

當掃描到第一塊陸地時，

```
□□111□□□
□□101□□□
□□111□□□
```

便交由另一個函式負責把整座島全部處理掉。

處理完成後，

```
□□000□□□
□□000□□□
□□000□□□
```

主迴圈不用回頭，也不用重新思考。

只要繼續往下掃描即可。

---

# 主迴圈

```c
int island_count = 0;

for (每一格)
{
    if (grid[row][col] == '1')
    {
        island_count++;

        clear_island(row, col);
    }
}

return island_count;
```

主迴圈的責任非常單純：

- 搜尋
- 計數
- 呼叫子函式

---

# clear_island()

另一個函式則只負責一件事情：

> **把整座島清除。**

流程如下：

```
clear_island(row, col)

1. 超出地圖範圍
    return

2. 如果不是陸地
    return

3. 將目前位置改成 '0'

4. 往四個方向繼續搜尋

    上
    下
    左
    右
```

除了清除島嶼之外，它不需要考慮任何其他事情。

---

# 為什麼要清除？

假設一座島有 20 個格子。

如果沒有把它清除，

主迴圈之後還會再次掃描到同一座島的其他格子，

結果就會重複計數。

因此，每當找到一座新的島，

就立刻把整座島全部標記成已拜訪。

如此一來：

```
找到第一塊陸地
        ↓
島嶼數量 +1
        ↓
整座島全部清除
        ↓
主迴圈繼續搜尋
```

每座島就只會被計算一次。

---

# 這題真正教我的事

我覺得這題最有趣的地方，不是 DFS。

真正讓我印象深刻的是：

> **如何把一個問題拆成不同模組，各自負責自己的工作。**

```
主迴圈
    ↓
發現工作

clear_island()
    ↓
完成工作
```

每個函式都只有一個責任。

這種思考方式，其實和韌體開發非常相似。

很多大型系統都不是靠一個很大的 function 完成，

而是透過不同模組彼此合作，各自負責自己的工作。

```
Time Complexity : O(M × N)

Space Complexity : O(M × N)   // Recursive DFS 最差情況
```

# 學到的東西

LeetCode 前面的題目，比較像是在練習演算法技巧。

而第 200 題開始，我開始感覺自己是在設計一個系統。

真正重要的不只是 DFS，而是：

- 如何拆解問題
- 如何分配責任
- 如何讓不同模組彼此合作

這也是我認為這題最值得學習的地方。

題外話：如果我來命名這題

我會把 Number of Islands 改叫做 島嶼消消樂（Island Eliminator）。

因為這題真正的目標並不是一直數島，而是：

找到一座島 → 消除整座島 → 得一分。

當整張地圖都變成海洋時，遊戲結束，而最後的分數，就是島嶼的數量。
