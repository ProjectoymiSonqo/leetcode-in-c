# 9. Palindrome Number

## 問題拆解

判斷一個整數是否為回文數。

特殊情況：

- 負數一定不是回文。
- 0 是回文。
- 個位數一定是回文。

---

## 解題思路

先計算整數共有幾位數。

之後利用最高位與最低位開始比較。

例如：

```
123321

1 2 3 3 2 1
↑         ↑
```

若左右相同：

```
i--
j++
```

繼續往中間比較。

若左右不同：

立即回傳 `false`。

全部比較完成後回傳 `true`。

---

## 核心機制

利用位數取得左右兩端的數字。

最高位：

```c
(y / (int)pow(10, i - 1)) % 10
```

最低位：

```c
(y / (int)pow(10, j)) % 10
```

比較完成後：

```
i--
j++
```

持續向中間收縮。

---

## Design Pattern

### Two Pointer（雙指標）

雖然資料型態是整數，

但思考方式與字串回文完全相同。

```
Left <---------> Right
```

每次比較：

```
Left == Right ?
```

如果相同：

```
Left++
Right--
```

直到左右交會。

---

## Trade-off

第一版選擇直接利用位數取得指定位置的數字。

優點：

- 思路直觀。
- 不需要額外建立陣列。
- 不需要轉換成字串。

缺點：

- 每次都需要呼叫 `pow()`。
- 需要重複做整數除法。

---

## 我學到什麼

第五題與第九題本質上是同一個問題。

第五題：

```
Palindrome String
```

第九題：

```
Palindrome Integer
```

不同的是：

第五題直接利用 index 存取左右字元。

第九題則利用位數取得左右兩端數字。

雖然資料型態不同，

但核心概念都是：

**由外往內逐步縮減比較範圍。**

---

## Debug 紀錄

一開始只設定：

```c
result = false;
```

但程式仍然會繼續往下執行，

導致負數進入後續流程，

最後發生：

```
pow(10, -1)
```

造成除以 0 的 Runtime Error。

修正方式：

特殊情況直接：

```c
return false;
```

或：

```c
return true;
```

避免已知結果仍然繼續執行後續流程。

這也讓我了解到：

> **設定答案，不代表流程停止。**

如果某個條件已經可以確定答案，

應該直接 `return`。
